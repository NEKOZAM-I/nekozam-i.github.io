How I learned Git (story time)

This is actually a long story but will shorten it up.

Aug 1, 2026 · 7 min read

So here's the story. A while back, I saw people using Git everywhere. Me being the type of person who wants to try every new thing, I immediately installed it. Notice how I said installed, not learned. That's just how I am. I install things first and figure them out later. Unsurprisingly, after installing Git, I didn't touch it again for months.

What is Git?

For anyone who doesn't know, Git is a free and open source version control system used to track changes in code over time. It was created by Linus Torvalds in 2005 and allows multiple developers to work on the same project without overwriting each other's work.

Instead of saving completely new copies of a project every time you make a change, Git stores snapshots of your project. Every developer has their own copy of the repository, works on it independently, and once they're happy with the changes, they can push them back to the main repository.

What I did

At first, I thought Git was some incredibly difficult tool that only experienced developers could understand. I watched a few tutorials, but nothing really clicked. Eventually, I came across Harvard's CS50 Web course[1], and everything suddenly made sense. Their visual explanations helped me understand what Git was actually doing instead of just showing me commands to copy and paste.

Once I understood the basics, I started uploading all of my old projects to GitHub. If you visit my GitHub today, you'll even find a QR Code Generator repository that I uploaded recently. It's not exactly a revolutionary project, but I wanted every project I'd built to have a place online.

Looking back, Git turned out to be much simpler than I had imagined. The hardest part wasn't learning Git itself. It was understanding what problem it was trying to solve. Once that clicked, everything else became much easier.

Now I use Git almost every day, and whenever one of my friends wants to learn it, I always try to explain the idea before teaching the commands. Understanding the concept first makes the commands feel much more natural.
